## [Unreleased]

### Added
- Vitest test runner wired up; core engine types (`PlayerState`, `StateCommand`, `MinigameLauncherPayload`, etc.) in `src/engine/types/index.ts`.
- Zod content schemas for Settlement, District, POI, Actor, Faction, and Endeavor.
- Zustand player store (`src/engine/store/`), CQRS-style: UI dispatches `StateCommand`s, pure command handlers in `commands.ts`, an in-memory (non-persisted) event log.
- Starter content vertical slice: Valdeombra, the Lantern Ward, the Crooked Hour tavern, Mara Venn, the City Watch faction, and "The Missing Broadsheet" endeavor.
- UI shell: `WorldClockHud`, `WorldNavigationView`, `NodeInteractionCanvas`, `ManagementDrawer`, `AssetFallback`, `MinigameOverlay`, composed in `App.tsx`.
- Dice minigame: 2d6 even/odd resolution, wager stepper (5–100 bronze), tabletop dice UI with a roll animation, wired into a "Gamble" action at the tavern.
- Mara Venn reputation loop: +5 reputation per conversation, auto-starts "The Missing Broadsheet" endeavor on first talk, unlocks a new dialogue line and auto-advances the endeavor phase at 10 reputation, "Pay off the buyer" action to spend 1 silver at the final phase.
- `faction_wagering_ring` content (Mara Venn's actual affiliation).
- `COMMAND_CANCEL_MINIGAME` and a "Leave" button on the Dice minigame, so it can be exited without forcing a win/lose outcome.
- `npm start`: installs dependencies, starts the dev server, and opens the game in the browser at the correct base-prefixed URL.
- `.nvmrc` and `package.json` `engines` field so local and CI Node versions can't silently drift apart.
- `content-integrity.test.ts`: every file under `src/content/` is automatically validated against its schema, so new content needs no test changes to be covered.
- `verify-phase` and `ui-visual-check` project skills (`.claude/skills/`) codifying this repo's per-phase Definition of Done and occasional real-browser verification pattern.
- Sound-effect system: a shared, deliberately fail-silent `playSound` utility (`src/engine/audio/`), dice win/lose SFX, and an optional `entrySoundAsset` field on District/POI content (with a placeholder demonstrating the fail-silent path on both the tavern POI and its district).
- `COMMAND_CANCEL_MINIGAME` follow-up sibling in spirit: a dev-only "Reset Progress" button in `ManagementDrawer`, resetting `PlayerState` to `initialPlayerState` for verification purposes (see `docs/decisions.md`).
- `docs/feature-workflow.md` and `docs/features/` — a structured spec process for future feature/content work, with referential-integrity checks added to `content-integrity.test.ts` (Actor↔Faction, POI↔Actor, District↔POI cross-references) as part of the same pass.
- Branching dialogue system: `DialogueSchema`/`DialogueNodeSchema`/`DialogueChoiceSchema`/`DialogueRequirementSchema` (`src/content/schemas/dialogue.schema.ts`), a `DialogueRequirement` evaluator (`src/engine/utils/evaluator.ts`), two new commands (`COMMAND_ENTER_DIALOGUE_NODE`, `COMMAND_SELECT_DIALOGUE_CHOICE`), a `DialogueOverlay` component, and `dialogueProgress` persisted on `PlayerState`. Mara Venn's dialogue is now a real branching tree (`src/content/dialogues/dialogue_mara_venn.json`) with a reputation-gated choice, choice-triggered consequences, and an ending choice with consequences.
- Referential-integrity checks in `content-integrity.test.ts` extended to cover `Actor.dialogueId -> Dialogue` and dialogue node id/reference consistency.
- `src/contentLoader.ts`'s `loadContent(schema, data, label)`: every content JSON file `App.tsx` imports is now run through its Zod schema at load time (throwing a clear error on failure) instead of consumed as a raw static import — closes the class of gap where a schema field's `.default(...)` was never applied to unparsed production content, even though `content-integrity.test.ts`/`schemas.test.ts` always passed (see Fixed, below, and `docs/decisions.md`).
- Rapier Duel minigame: a turn-based `DUEL` mechanic (`src/engine/minigames/duel.ts`) — five actions (Thrust, Parry & Riposte, Feint, Taunt, Dirty Trick) resolved deterministically against an energy/poise stat pair and a three-step distance track, a guard-break bonus for hitting an already-broken guard, and a reputation-gated Taunt bonus tied to `faction_wagering_ring`. `DuelGame.tsx` presentation component, wired into `MinigameOverlay`. Engine-only this phase — no in-content trigger yet (see `docs/features/feature_rapier_duel.md`).

- Item content type (`ItemSchema`, `src/content/items/item_rapier.json`): `id`, `name`, `description`, a required `imageAsset`, and a `stackable` flag, loaded through `loadContent` like every other content type. The inventory tab in `ManagementDrawer` now resolves an owned item's display name, description, and image instead of showing the raw `itemId` string (falling back to the raw id for any unresolved item).
- Character Roster tab in the Journal drawer, listing actors the player has already met (name, title, portrait, description, affiliated faction(s)) — "met" reuses the existing `dialogueProgress` entry created the first time an actor's dialogue is opened, no new `PlayerState` field. Faction content (`faction_city_watch.json`, `faction_wagering_ring.json`) is now loaded in `App.tsx` for the first time (previously authored but never read anywhere) to resolve faction names. Every field in a roster row (portrait, name, title, faction line, description) renders conditionally, with no placeholder for a missing value.

- `activeDialogue: { dialogueId: string } | null` moves dialogue visibility into `PlayerState`, mirroring `activeMinigame` — a dialogue can now be opened by something other than an actor click. New commands `COMMAND_OPEN_DIALOGUE`/`COMMAND_CLOSE_DIALOGUE`, kept separate from `COMMAND_ENTER_DIALOGUE_NODE`'s pure-bookkeeping contract for the same reason it's already separate from `COMMAND_SELECT_DIALOGUE_CHOICE`; `COMMAND_CLOSE_DIALOGUE` mirrors `COMMAND_CANCEL_MINIGAME` exactly. `EndeavorPhase.autoDialogueOnEnter` lets a phase auto-open a dialogue when the player enters a POI while it's active — engine-only, no in-content trigger authored yet. `entrySoundAsset`'s old one-off trigger functions are now a typed `EntryEffect` (`SOUND | DIALOGUE`) registry (`src/engine/utils/entryEffects.ts`), resolving the smaller half of `game-design-spec.md` Open Design Gap #9. See `docs/features/feature_dialogue_visibility_and_auto_triggers.md`.
- `Endeavor.autoStartOnEnter` and a `START_ENDEAVOR` `EntryEffect` variant — a scene can now auto-*start* an endeavor (`COMMAND_START_ENDEAVOR` + open its dialogue) on POI entry, not just auto-trigger a dialogue within one already active. Gated on the new `isNodeUnlocked` helper (below) so a locked endeavor can't auto-start. A second entry-trigger path — a `useEffect` watching `activeEndeavors` — fires an applicable `autoDialogueOnEnter` for the POI the player is *already standing in* when a phase change makes it newly applicable, filtered to `DIALOGUE`-only effects and guarded on no dialogue already being open. See `feature_dialogue_visibility_and_auto_triggers.md`'s addendum.
- `isNodeUnlocked(node, nodeId, unlockedNodes)` helper (`src/engine/utils/`) — merges a node's static `isUnlocked` content default with the dynamic, player-earned `unlockedNodes` record (confirmed monotonic: nothing ever sets an entry back to `false`). Applied to `NodeInteractionCanvas`'s actor list, which previously had no lock check of any kind — a locked actor now renders disabled with the same `"??? (locked)"` placeholder `WorldNavigationView` already used for POIs. See `docs/features/feature_node_unlock_rendering.md` and `docs/decisions.md`.
- "A Debt in Steel" (`endeavor_a_debt_in_steel`): a full seven-phase Endeavor at the Crooked Hour and a new POI, Widowmaker Alley (`poi_widowmaker_alley`) — the first real content to exercise `Endeavor.autoStartOnEnter`, the same-POI phase-change trigger (twice — tavern and alley), `isNodeUnlocked`-gated Actor/POI reveals outside their own test suite, and a dialogue-choice-triggered `DUEL` whose win/lose outcome opens a dialogue via `onSuccessCommands`/`onFailureCommands`. New Actors `actor_bookkeeper` (real, durable, reusable — not a text-only speaker label), `actor_anselm_draye`, `actor_duro_vantry`; new Item `item_vantry_rapier` (the win reward); eight new Dialogues (`dialogue_the_challenge`, `dialogue_bookkeeper_default`, `dialogue_anselm_recruit`, `dialogue_widowmaker_arrival`, `dialogue_the_offer`, `dialogue_reckoning_win`, `dialogue_reckoning_lose`, `dialogue_duro_vantry_default`). See `docs/features/content_a_debt_in_steel.md` and `docs/decisions.md`.

- Real artwork for `actor_anselm_draye`, `actor_bookkeeper`, and `actor_duro_vantry` (`.jpg`), replacing their `AssetFallback` MISSING placeholders.

- `ManagementDrawer`'s Endeavors tab now separates ongoing from completed Endeavors: completed ones move below a "Completed" divider, marked with a ✓ and dimmed, so the player can see at a glance what still needs attention. Reuses the same "no `nextPhaseOnSuccess` = terminal = complete" rule the notification system's completion toast already uses (new `phaseIsTerminal` prop, content-derived in `App.tsx`), so the split always agrees with what triggers a "Completed: ..." toast.
- `ManagementDrawer`'s Endeavors tab now shows each active Endeavor's current-phase `objectiveText` ("Someone paid good silver to keep that press silent...") instead of the raw phase id (`phase_confront_the_buyer`). New `phaseObjectives` prop (`endeavorId -> phaseId -> objectiveText`), content-derived in `App.tsx`, same pattern as `endeavorTitles`.
- "Pay off the buyer" now visibly acknowledges a click — briefly shows a disabled "Paid ✓" state (~1.2s) before reverting — instead of looking unresponsive between the click and the (easy-to-miss) currency toast. Purely cosmetic: the action is still deliberately repeatable with no one-time completion gate (`web-implementation.md` §3), unchanged by this.

- Notification system (`game-design-spec.md` §12): a transient, auto-dismissing on-screen toast whenever currency, an item, or Actor/Faction reputation changes, or an Endeavor completes. Store-only `notifications` (never persisted, mirroring `eventLog`), derived generically by diffing `PlayerState` before/after every `dispatchCommand` — correctly covers changes nested inside a dialogue choice's `commands` or a minigame's `onSuccessCommands`/`onFailureCommands`, not just top-level dispatches. Endeavor completion is detected separately, reactively, in `App.tsx` (the one case needing content awareness `src/engine/` can't have). New `NotificationTray`/`Toast` components (top-right, floats above every other overlay), `src/notificationResolution.ts` for content-aware display-text resolution. No new `CommandType` or schema change. See `docs/features/feature_notification_system.md`.
- A reusable, dependency-free `Tooltip` component (`src/engine/components/Tooltip.tsx`, CSS-only via Tailwind `group`/`group-focus-within`), applied throughout `DuelGame`: each action button explains what it does and when it's usable, the distance indicator explains what the current distance means and which actions it enables, and an `(?)` affordance next to Energy/Poise explains what each stat represents and what happens at 0.
- `DuelConfig.allowFlee?: boolean` (default `true`) — a content-authored duel can now disable the "Flee" button, replacing it with a short fallback line, for a duel with no way back in once fled (fleeing would otherwise permanently strand the triggering Endeavor mid-phase, with no re-trigger path). Set `false` on "A Debt in Steel"'s duel.
- Modifier system (`docs/features/feature_modifier_system.md`): a per-item stat-bonus layer, aggregated at query time from owned items rather than stored as accumulated buff state on `PlayerState`. New `src/engine/modifiers.ts` (`MODIFIER_KEYS`, `selectModifiers`, `applyModifiers` — `max(0, round((base + ΣFLAT) × (1 + ΣPERCENT)))`, exclusive targeting), `ModifierGrantSchema`/`ModifierSourceSchema` (`src/content/schemas/shared.ts`) composed into `ItemSchema`, and `src/modifierResolution.ts`'s `collectActiveModifiers` (owned-only, quantity-independent). `applyCommand` gains an optional `ctx: { modifiers? }` param, threaded through both existing recursion sites; `COMMAND_ADJUST_CURRENCY`/`COMMAND_ADJUST_REPUTATION` derive `CURRENCY_GAIN/LOSS`/`REPUTATION_GAIN/LOSS` from the sign of `amount`, scaling a bronze-equivalent magnitude before reapplying the sign. An optional `modifierKey` payload override lets the dice minigame tag its payouts `CURRENCY_GAMBLING_WINNINGS` — a key no item can be authored against — so an item's currency bonus can't turn dice's EV-neutral odds positive-EV. `DuelContext` gains a `modifiers` field; `src/engine/minigames/duel.ts` wires only `DUEL_DAMAGE_DEALT` this phase (every hit/counter-hit the *player* lands), leaving `DUEL_DAMAGE_TAKEN`/`DUEL_STARTING_POISE` reserved but unwired. Store-only, non-persisted `activeModifiers` (`playerStore.ts`), recomputed by an `App.tsx` `useEffect` on `inventory`. Duel action tooltips (`DuelGame.tsx`) now surface active `DUEL_DAMAGE_DEALT` modifiers by source. Three new items: `item_duellists_rapier` (+3 flat duel damage), `item_letter_of_introduction` (+25% reputation gain, targeted at `faction_city_watch`), `item_pendant_of_easy_coin` (+5% currency gain) — authored, not yet reachable through any content acquisition path. Equipping (a `slot`/`equipped` concept) explicitly deferred until a second item competes for the same role.
- Localization (`docs/features/feature_localization.md`): a header-level `LanguageSelector` (English default, Português — Brasil, mounted inside `WorldClockHud`) switching both UI chrome and translated content live. Two independent tracks: engine/UI strings via i18next + react-i18next (`src/engine/i18n/` — bundled `en.ts`/`pt-BR.ts` dictionaries, both typed against one `LocaleDictionary` interface so a missing/extra key is a compile error), and content via locale overlay files (`<id>.<locale>.json`, e.g. `actor_mara_venn.pt-BR.json`) carrying only the translatable subset of a content type's fields, merged onto the canonical English file at render time by `src/contentLocalization.ts`'s `loadLocalizedContent`, falling back to English per-field when a translation is missing or the overlay file doesn't exist at all. New overlay schemas (`BaseNodeTranslatableSchema`, `ActorTranslatableSchema`, `EndeavorTranslatableSchema`, `DialogueTranslatableSchema`) and a `LOCALES`/`Locale` type (`src/engine/types/index.ts`). Locale selection lives in a second, independent Zustand store (`useLocaleStore`, its own `persist` key) — never part of `PlayerState`, so it doesn't travel with an exported/imported save. The three previously-triplicated currency-formatting implementations (`WorldClockHud`, `DiceGame`, notification currency deltas) are unified into one locale-aware formatter routed through i18next's plural rules. Every enum's underlying identifier (`Shift`, `DistanceState`, `MinigameType`, etc.) stays fixed and locale-invariant forever; only its rendered label localizes.
- Every content file in the project now has a `pt-BR` overlay (all 26: settlements, districts, POIs, actors, factions, endeavors, dialogues, items) — the initial phase above shipped one vertical slice as proof; this fills in the rest. Surfaced and fixed a real gap in the process: `App.tsx`'s locale resolution had been a hardcoded six-entity list, so Endeavor titles/objective text and Item names/descriptions were silently never localized despite valid overlay files existing for them (caught once those files existed and were actually tested, not by inspection). Fixed by generalizing the resolution to map `applyLocaleOverlay` generically over every content array instead of extending the hardcoded list — a new overlay file for any existing content id is now picked up automatically, with no `App.tsx` code change required. See `docs/decisions.md`.
- `LanguageSelector` now shows a small flag icon (US for English, Brazil for pt-BR, `FlagIcon.tsx`, inline SVG) next to every language option — on the closed control AND inside the open dropdown list. Went through two narrower attempts first, both replaced after real browser testing: emoji inside a native `<option>` rendered as plain "US"/"BR" text on Windows (its bundled emoji font never renders flag emoji as a picture, on any Windows version, in any browser); an inline SVG placed only on the closed control fixed that but still couldn't show a flag inside the dropdown list itself, since a native `<option>` can only ever hold plain text, never an image. `LanguageSelector` is now a custom button+listbox (`role="listbox"`/`role="option"`, closes on Escape or an outside click) instead of a native `<select>`, trading away the browser's built-in `<select>` behavior for a flag actually rendering everywhere the language name does.
- `.claude/skills/work-next-issue/`: a new skill that autonomously picks the next backlog issue off the GitHub Project board and drives it through `docs/feature-workflow.md`'s full stage sequence end to end — selection, spec draft, `design-review`, implementation, `verify-phase`'s Definition of Done, reachability, docs sync, commit/push, and issue close — without a human confirmation gate before the final push, by design. Six real gaps surfaced by recent work filed as detailed backlog issues (#5-#10: missing CI build step, stale `execution-plan.md`, fragile `DialogueNode.speaker` matching, `importSave`'s missing UI, i18next's missing key type-safety, and a `CONTRIBUTING.md`-vs-actual-practice branching conflict found while writing this skill). Also fixed: issues #3/#4 had been created but never added to the Project board — no automation does that — added retroactively as Done, and #5-#10 added as Backlog. See `docs/decisions.md`.

### Changed
- `DuelGame`'s log now shows human-readable action names (`ACTION_LABELS`, `src/engine/minigames/duel.ts`) instead of the raw `DuelAction` enum (`DIRTY_TRICK` → **Dirty Trick**), bolded in the log line; the action buttons now source their labels from the same shared map instead of a separately hand-maintained list.
- `DialogueOverlay` no longer wraps `node.text` in its own curly quotes — content is free to mix third-person narration with its own quoted speech (as "A Debt in Steel"'s dialogues do throughout) without the two levels of quotation doubling up.
- Speaker-portrait resolution in `App.tsx` switched from matching `Actor.dialogueId` against the currently open dialogue to matching `DialogueNode.speaker` against `Actor.name` — an Actor's portrait now resolves correctly in *any* dialogue they speak in (a scripted scene, a minigame's win/lose reckoning dialogue), not only their own home dialogue.
- `COMMAND_ADJUST_CURRENCY` now borrows down (silver/gold break into bronze on a loss) and enforces a hard zero floor, not just carry-up on gains.
- Mara Venn's faction corrected from `faction_city_watch` to `faction_wagering_ring`; title and description updated to match ("Wagering Ring Regular").
- Player now starts with a small currency purse (50 bronze-equivalent) instead of zero, so the gambling loop is reachable from a fresh save.
- `StateCommandSchema` restructured from a loose `{ type, payload: Record<string, unknown> }` schema into a `.strict()` discriminated union, one payload schema per command — a malformed or extra-keyed content-authored command payload now fails validation at test/CI time and on save-file import instead of silently passing.
- **Breaking:** `Actor.initialDialogue: string` replaced by `Actor.dialogueId: string`, pointing at a `Dialogue` content file. No backward-compatibility layer — one actor in the project, no live players.
- Mara Venn's reputation gain, endeavor start, and endeavor phase advance moved from unconditional `App.tsx` click-handler side effects into `commands` on specific dialogue choices — reputation now accrues from engaging in the conversation, not from any click on her name. `NodeInteractionCanvas` no longer renders dialogue text directly; `DialogueOverlay` (mounted as an `App.tsx`-level sibling, like `MinigameOverlay`) does.
- `MinigameLauncherPayload.config` is now a discriminated union keyed on `type` (`DiceConfig | DuelConfig` for the two resolved mechanics; `LOCKPICKING`/`FISHING` keep the old untyped bag) instead of a single `Record<string, unknown>` for every type.
- `DialogueOverlay` drops its `onClose` prop, following `MinigameOverlay`'s existing precedent — closing now dispatches `COMMAND_CLOSE_DIALOGUE` directly. Speaker-portrait resolution switched from matching the clicked actor (`selectedActorId`) to a `dialogueId` reverse lookup (`actors.find(a => a.dialogueId === ...)`), so it resolves correctly for an auto-triggered dialogue too, not just a click.
- `formatCurrencyDelta` moved from `src/engine/store/notifications.ts` to `src/engine/i18n/formatCurrency.ts` and now takes a `TFunction` — a currency-change notification now reads "+3 Gold Coins, 1 Silver Coin" instead of "+3 Gold, 1 Silver" (routed through i18next's plural rules, correct in Portuguese too, not just English's invariant wording).

- **Breaking (content-only, no live players):** `District/POI.entrySoundAsset`, `EndeavorPhase.autoDialogueOnEnter`, and `Endeavor.autoStartOnEnter` — three independently-invented ad-hoc shapes for the same "when this condition is met, run these effects" idea — unified into two shared, composable Zod schema fragments: `TriggerableSchema` (`onEnter: EntryEffect[]`, District/POI — unconditional, node-local) and `PoiEntryTriggerSchema` (`{ poiId, onEnter: EntryEffect[] }`, `EndeavorPhase.onPoiEnter`/`Endeavor.onPoiEnter` — targeted, removing what were two independently-declared byte-identical `.strict()` objects). `EntryEffect`/`EntryEffectSchema` moved from `src/engine/utils/entryEffects.ts` into `src/engine/types/index.ts` (the shared engine/content vocabulary), now directly content-authorable. Behavior-preserving: `district_lantern_ward.json`, `poi_crooked_hour_tavern.json`, and `endeavor_a_debt_in_steel.json` (4 triggers) migrated to the new shape with no functional change, verified via a full manual playthrough of "A Debt in Steel"'s auto-trigger chain. See `docs/features/feature_triggerable_effects.md`.

### Fixed
- CI pinned to Node 20 while local development used Node 24, causing jsdom's `undici` dependency to fail only in CI (`markAsUncloneable` missing pre-v21). CI bumped to Node 24, then centralized into `.nvmrc` as the single source of truth.
- The Dice minigame modal had no way to close once opened if the player couldn't afford the minimum wager — no cancel, only a disabled "Throw."
- `npx tsc --noEmit` (bare) was silently checking zero files project-wide (no `-b` to follow `tsconfig.json`'s project references) — every "clean type-check," including in CI, was vacuous. Fixed to `npx tsc -b --noEmit` everywhere it's used; fixed the one genuine type error it had been hiding.
- A dialogue choice omitting `commands` crashed at runtime (`commands is not iterable`) despite passing every test — `App.tsx`'s raw static content import never applied `DialogueChoiceSchema.commands`'s `.default([])`, only `content-integrity.test.ts`'s own internal `schema.safeParse` did. Root-caused via the new `loadContent` mechanism above, not a per-field patch.
- Every content-authored asset path (`imageAsset`, `entrySoundAsset`) was written as a root-relative string (`/content/assets/...`), but the app builds with a non-root Vite `base` (`/broadsheet-rapier/`) — so any real asset 404'd under that base, both in dev and in the GitHub Pages build. Invisible until now because no real asset file existed yet for any content type; surfaced the moment `item_rapier`'s actual artwork was added and still showed the MISSING placeholder. Fixed with a shared `resolveAssetUrl` helper (`src/engine/utils/`), applied at the two places a path becomes a real `src`/`Audio()` call: `AssetFallback` and `playSound`.
- **`WorldNavigationView`'s POI lock indicator was silently non-functional for the entire project history — a real behavior change to already-shipped code, not new scope.** It read only the static `Poi.isUnlocked` content field; `PlayerState.unlockedNodes` (written by `COMMAND_UNLOCK_NODE`/`EndeavorPhase.unlocksNodesOnComplete`) was never consulted, so a POI's lock state could never actually change at runtime — every unlock command dispatched so far had zero visible effect. Now reads `isNodeUnlocked(poi, poi.id, unlockedNodes)`. See `docs/features/feature_node_unlock_rendering.md` and `docs/decisions.md` for the full finding.
- `DialogueOverlay` now has a "Close" button to leave a conversation without picking a choice, and shows the current speaker's portrait (resolved by `App.tsx` from the open dialogue's Actor).
- Dice minigame's result now labels the roll as Even/Odd alongside the sum, and the result button reads "Continue" (not "Collect") on a loss, since nothing is collected.
- Journal drawer (`ManagementDrawer`) widened from `w-80` (320px) to `w-[30rem]` (480px, 50% larger) for readability.
- `WorldClockHud` now shows an emoji icon next to Shift, Season, and Weather (e.g. 🌧️ for RAIN) — plain emoji, not image assets, so no path-resolution or missing-asset risk.
- Dev-only World Clock tools in the Journal drawer (`ManagementDrawer`, alongside Reset Progress): cycle Shift/Season/Weather, increment/decrement Day. Bypasses the `StateCommand` pipeline via a new store-native `devSetWorldClock` action (mirrors `resetProgress`'s precedent), not a dispatchable command.
- `.github/workflows/deploy.yml`: builds and publishes the app to GitHub Pages on every push to `main` (and via manual dispatch), using `actions/upload-pages-artifact` + `actions/deploy-pages`. `vite.config.ts`'s `base` was already correctly set to `/broadsheet-rapier/` (confirmed via a local `npm run build`, checking the built `index.html`'s asset paths). README now links the live Pages URL.
- CI (`npm run lint`) failed on commit `a50473b` — `duel.ts`'s `player`/`opponent` were declared `let` but only ever mutated via property assignment, never reassigned (`prefer-const`). `tsc`/`npm run test` don't run ESLint, so this shipped past local verification undetected; caught only by CI actually running. Changed to `const`.
